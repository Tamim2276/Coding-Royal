# JSON Web Tokens (JWT) Explained (The Easy Way)

## What is a JWT?

Think of a JWT as a **digital VIP Pass** for your application.

When a user logs in with their correct username and password, the server (ASP.NET Identity) checks the database. If everything is correct, the server doesn't want the user to keep sending their password on every single request (like when they try to join a match).

Instead, the server generates a JWT, signs it, and gives it to the user. For all future HTTP requests, the user just shows this VIP Pass in their request headers to prove who they are.

---

## The JWT Setup Code, Explained

In `Program.cs`, we use a block of code to set up the rules for this VIP pass. Here is what it means in plain English:

### 1. Activating JWT

```csharp
builder.Services.AddAuthentication(options =>
{
    options.DefaultAuthenticateScheme = JwtBearerDefaults.AuthenticationScheme;
    options.DefaultChallengeScheme = JwtBearerDefaults.AuthenticationScheme;
})
```

This tells your application's Security Guard:
_"We are using digital VIP Passes (Bearer tokens) as our only form of ID. Don't ask for session cookies. If they don't have a valid Token, reject them (HTTP 401 Unauthorized)."_

### 2. The Checklist (Validating the Token)

The `TokenValidationParameters` is the strict checklist the Security Guard must go through _every single time_ someone hands them a VIP Pass.

#### A. The Secret Signature (Anti-Forgery)

```csharp
ValidateIssuerSigningKey = true,
IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(jwtSettings["Secret"]!)),
```

- **Explanation:** Your API has a private "Secret" key string in `appsettings.json`. It uses this to cryptographically sign the tokens it creates.
- **Analogy:** The guard shines a UV light on the VIP pass. If it doesn't show your exact shiny hologram (the Secret signature), it means a hacker tried to forge the pass, and it gets thrown out.

#### B. The Issuer (Who made it?)

```csharp
ValidateIssuer = true,
ValidIssuer = jwtSettings["Issuer"],
```

- **Explanation:** Checks if the tokens were actually generated by your API (e.g., `ClashOfCodesAPI`).
- **Analogy:** The guard checks the logo printed on the pass. If the pass says it was issued by "Roblox" instead of your API, it's rejected.

#### C. The Audience (Who is it for?)

```csharp
ValidateAudience = true,
ValidAudience = jwtSettings["Audience"],
```

- **Explanation:** Checks if the token is meant for the correct audience (e.g., `ClashOfCodesPlayers`).
- **Analogy:** If you have an Admin party and a Player party, the guard checks if this VIP pass is actually for the Player Section, preventing people with Admin passes from a totally different system from wandering in.

#### D. The Expiration Date (Is it too old?)

```csharp
ValidateLifetime = true,
ClockSkew = TimeSpan.Zero
```

- **Explanation:** Ensures the token hasn't expired.
- **Analogy:** Tokens usually expire after a few hours or days. `ClockSkew = TimeSpan.Zero` tells the guard to be extremely strict—if the pass expired 1 second ago, do not let them in! No grace periods.

---

## Summary

1. Users log in with a password **once**.
2. The server hands them a **JWT (VIP Pass)**.
3. The JWT contains their User ID, their roles, and an expiration date, all sealed with a **Secret Signature**.
4. The user sends the JWT in the `Authorization` HTTP header every time they click a button in your app.
5. The `TokenValidationParameters` code checks the signature and expiration date before letting the code run.
